STEELCONTROL — FACE SECURITY V12

O que mudou
- Cadastro facial de funcionário exige imagem frontal + prova de vida por movimento.
- O backend confirma que as duas imagens pertencem à mesma pessoa.
- Enrollment usa limiar de duplicidade mais conservador (0.50) e compara frontal + liveness.
- Advisory lock PostgreSQL continua serializando cadastros simultâneos.
- Tentativas de rosto já vinculado são bloqueadas e registradas na auditoria.
- Ao detectar FACE_ALREADY_LINKED, o Desktop para a câmera, fecha o modal e avisa o administrador.
- Rate limit específico foi adicionado ao cadastro facial.
- Cadastro inicial da empresa e /auth/face/register-image receberam o mesmo endurecimento de duplicidade/liveness.
- Ferramenta de diagnóstico: backend -> npm run face:audit

IMPORTANTE SOBRE DUPLICIDADES QUE JÁ EXISTEM
Este patch impede novos cadastros duplicados, mas não apaga automaticamente uma biometria já gravada antes do patch, porque o sistema não pode decidir sozinho qual perfil é o legítimo.
1. Na pasta backend, rode: npm run face:audit
2. Revise os pares apontados.
3. Em Minha Empresa -> Funcionários -> Gerenciar facial, remova a biometria incorreta.

Depois de extrair
1. Reinicie o SteelControl.
2. No navegador use Ctrl + F5 uma vez.
3. Teste com uma facial já existente: o cadastro deve ser bloqueado, a câmera deve fechar e o aviso deve aparecer.

Limite técnico
Nenhuma biometria pode ser declarada 100% segura. Esta versão endurece fortemente o enrollment e a duplicidade, mas implantação empresarial crítica ainda deve incluir anti-spoof/liveness especializado, calibração FAR/FRR, proteção de dados biométricos e política LGPD.
